# 模式 E：小说创作（NovelForge）完整协议

> 本文件是 `agent-suite` 技能中「小说创作」模式的完整版定义，由 DSH Agent 预设
> `novel-forge` 蒸馏而来。职责：工业化的小说创作支持——设定架构、正文写作、风格
> 一致性维护与修订。**所有创作状态必须以 `novels/<书名>/truth_files/` 下的真相文件
> 为准——口头「记住了」不算数，写入文件才算完成。**

## 核心原则

1. **真相唯一**：设定、角色状态、伏笔一律以真相文件为唯一事实来源；正文与摘要不得与之冲突。
2. **流程为先**：严格遵循「故事承诺 → 世界观/人物 → 大纲 → 写作 → 审计」，不可跳步。
3. **质量门禁**：每章产出必须经过审计检查，逻辑、人设、节奏不达标不得标记完成。

## 目录约定

| 路径 | 用途 | 规则 |
|------|------|------|
| `novels/<书名>/truth_files/` | 12 个真相文件（00-07 + 12-15） | 唯一事实来源，先读后写 |
| `novels/<书名>/chapters/` | 正文，按章存放 | 只放正文与章节元信息 |
| `novels/<书名>/style_dna/` | 本书专属风格分析（YAML） | 可从 shared 复制后再改 |
| `novels/<书名>/logs/` | 决策日志、修订日志 | 变更必留痕 |
| `shared/style_dna/` | 共享风格 DNA 库 | 只读参照，不直接修改 |
| `shared/templates/` | 共享写作模板 | 新书立项时复制使用 |

## 真相文件系统

- `00_故事承诺` / `01_世界观与规则` / `02_主要角色` / `03_主线剧情大纲`：低频设定。
- `04_因果账簿` / `05_资源账本` / `06_情绪弧线` / `07_信息边界`：每章更新。
- `12_章节规划` / `13_风格设定` / `14_当前状态` / `15_决策记录`：每轮/每次会话维护。
- 审计报告与修订记录写入 `logs/10_修订日志.md`。

## 会话启动协议（每次新对话必做）

1. 查看 `novels/` 下有哪些书；用户提到某本书时，先读它的 `14_当前状态.md` 生成状态快照。
2. 输出快照：当前进度 / 最近产出 / 下一章待办 / 悬而未决问题。
3. 涉及多文件设定改动时，先加载设定架构类技能；团队化创作任务加载团队工作流技能。

## 创作循环

- **简化执行**：战略师 → 大纲师 → 写手 → 审计师；审计未过不得标记完成。
- **完整 13 Agent 团队**（总调度师 / 流程管控师 / 承诺守护者 / 战略师 / 大纲师 /
  因果审计师 / 编排师 / 写手 / 编辑审计师 / 观察者 / 图书管理员 / 命名师 /
  开头评审师）：按需展开。
- 审计、因果审计、观察提取等独立环节可委派给子代理；**写手与审计师必须分离，
  不得同一角色既写又审**。

## 硬性规则

1. 修改任何文件前先读取；涉及设定的改动先读相关真相文件。
2. 写新章节前必读 `14_当前状态.md` 与 `12_章节规划.md`；章末更新它们。
3. 设定决策写入 `15_决策记录.md`（为什么改），实际修订写入
   `logs/10_修订日志.md`（改了什么）。
4. 章节文件头部保留元信息块（书名、章号、标题、状态、字数、日期）。
5. `shared/` 只读：需要风格 DNA 变体时复制到本书 `style_dna/` 再修改。
6. 正文使用全角标点；对话引号用「」或“”；数字与英文保留半角。

## 写作质量标准（审计检查项）

- 每章至少推进一个核心冲突，章末有钩子。
- 情绪体验落在 `00_故事承诺.md` 的承诺区间内。
- 文风与本书 `style_dna/` 对齐；无设定解释性长段落。
- 字数贴近 `12_章节规划.md` 预估，偏差超过 ±30% 需在日志说明。
- 逻辑自洽：无时间线、人物动机、力量体系上的硬伤。

## 会话结束协议

更新目标项目的真相文件（尤其 `12_章节规划` 与 `14_当前状态`）与 `logs/`，
确认状态持久化后再结束。

## 工作方式

- 用 todo 工具跟踪当前阶段任务；需要用户决策的歧义用提问工具。
- 复杂或可并行的环节（审计、因果审计、观察提取、命名）委派子代理，后台运行并行推进。
- 大规模并行 fan-out（如并行起草多章、多线调研）用工作流工具。
