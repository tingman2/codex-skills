# VFD 流程图 JSON 格式规范（v1）

> 用途：让「流程规划师 Agent」直接产出 **VFD（VUE FLOW DESIGN 流程设计器）** 可导入的 JSON
> 流程文件，用户可在本地运行的 VFD 工程中打开、拖拽微调、改属性，并重新导出 JSON 回注 Agent 迭代。
> 规范依据 VFD v1.0.5 源码（`flow-designer-vfd/`，导入逻辑见
> `src/components/flow/designer/FlowDesigner.vue` 的 `loadFlow()`）逆向整理，字段缺失会导致加载失败或渲染空白。

---

## 1. 文件顶层结构

```json
{
  "nodeList": [ ...节点... ],
  "linkList": [ ...连线... ],
  "attr":  { "id": "flow-<标识>-<yyyyMMdd>" },
  "config": { "showGrid": true, "showGridText": "隐藏网格", "showGridIcon": "eye" },
  "status": "1",
  "remarks": []
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `nodeList` | Array | ✅ | 节点数组（顺序即绘制层级：**靠前在底层**，泳道容器必须排最前） |
| `linkList` | Array | ✅ | 连线数组 |
| `attr.id` | String | ✅ | 流程 id，仅展示用，需唯一可读：`flow-订单售后-20260601` |
| `config` | Object | ✅ | `showGrid` 网格开关，缺失会报错 |
| `status` | String | ✅ | 用 `"1"`（SAVE）。取值：`0` 新建 / `1` 保存 / `2` 修改 / `3` 加载中 |
| `remarks` | Array | ✅ | 备注，可留空 `[]` |

---

## 2. 节点（nodeList 元素）

### 2.1 支持的 9 种类型（来自 `config/basic-node-config.js`，别用其他 type）

| type | 含义 | 形状 | 建议尺寸 w×h (px) |
|---|---|---|---|
| `start` | 开始 | 圆形 | 50 × 50 |
| `end` | 结束 | 圆形 | 50 × 50 |
| `common` | 人工节点（步骤） | 圆角矩形（带人形图标） | 120 × 50 |
| `freedom` | 自动节点（系统步骤） | 圆角矩形（带同步图标） | 120 × 50 |
| `gateway` | 网关/判断 | 菱形（**判断问题文字写在菱形内部居中**，条件走向写连线 label） | 150 × 65 |
| `event` | 事件节点 | 圆形 | 50 × 50 |
| `child-flow` | 子流程 | 圆角矩形（带 api 图标） | 120 × 50 |
| `x-lane` | 横向泳道（容器） | 横向矩形 | 高 ≥200，宽随内容（见 §4） |
| `y-lane` | 纵向泳道（容器） | 纵向矩形 | 200 × 600 |

### 2.2 节点字段

```json
{
  "type": "common",
  "nodeName": "客服受理工单",
  "id": "common-1",
  "x": 220,
  "y": 80,
  "width": 120,
  "height": 50
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `type` | ✅ | 必须是上表 9 类之一 |
| `nodeName` | ✅ | 节点显示文字（泳道节点显示为泳道标题） |
| `id` | ✅ | **文件内唯一**；建议 `类型-序号`（`common-1`），连线上引用它 |
| `x` / `y` | ✅ | 左上角坐标，**≥0 且为 5 的倍数**（画布 5px 对齐网格） |
| `width` / `height` | ✅ | 见类型表；x/y 指节点左上角，绘图/碰撞都以它为锚 |

> 节点渲染只读 `type / nodeName / x / y / width / height / id`。属性面板只能改 `nodeName`。
> 不需要 `icon` 字段（图标由前端按 type 决定）。

---

### 2.3 判断节点文案规范（gateway + 分支 label）
- **能用"是/否"回答的判断**：gateway 的 nodeName 写成可回答是/否的问题（如 `今日已签到？`、`已有设备身份 sd_uid？`），
  出边 label 用 `是（后果/去向）` 与 `否（后果/去向）`——括号里给一句话结果或去向，帮助阅读。
- **非二值条件判断**（金额、时间、数量等取值区间）：nodeName 描述被判断的条件（如 `报销金额判断`），
  每条出边 label 直接写条件文本（如 `金额 ≤ 1000` / `金额 > 1000`），不用是/否。
- gateway 的 nodeName（判断问题）**写在菱形内部居中显示**（flow-designer-vfd 已支持内嵌文字渲染，菱形用 150×65）；
  出边 label 负责区分流向（是/否或条件文本），二者配合阅读。

## 3. 连线（linkList 元素）

```json
{
  "type": "link",
  "id": "link-1",
  "sourceId": "gateway-1",
  "targetId": "common-2",
  "label": "是新用户",
  "cls": {
    "linkType": "Flowchart",
    "linkColor": "#2a2929",
    "linkThickness": 2
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `type` | ✅ | 固定字符串 `"link"`（属性面板据此识别为连线） |
| `id` | ✅ | 文件内唯一，建议 `link-序号` |
| `sourceId` | ✅ | 起始节点 id，必须存在于 nodeList |
| `targetId` | ✅ | 目标节点 id，必须存在于 nodeList；禁止与 sourceId 相同 |
| `label` | ⭐ | **连线文字**：判断分支条件 / 转移动作说明。可为空串 `""` |
| `cls` | ✅ | 样式三件套，照抄默认值即可（可调整颜色/粗细做条件线区分） |

规则：
- **同一对 (sourceId,targetId) 只允许一条同向连线**（编辑器手工连线会拦截重复；生成时直接避免）。
- 泳道容器节点（x-lane / y-lane）**不参与连线**（编辑器对泳道禁连）。
- **连线一律直角折线，禁止曲线**：`cls.linkType` 必须保持 `"Flowchart"`（jsPlumb 直角折线连接器）。
  不要使用 `Bezier` / `StateMachine` / `Straight`（曲线或斜线）——目标观感与 VFD 工程一致：
  节点方正、连线横平竖直、只带直角拐弯。

## 4. 布局规则（Agent 排版约定）

LLM 直接输出坐标会叠成一团，必须按下述简单"层排 + 泳道"规则计算坐标，保证 5px 对齐。

### 4.1 节点坐标语义
`x/y` = 节点**左上角**。连线由 jsPlumb 自动吸附四边中点（Bottom/Right/Top/Left），无需给出路径点。

### 4.2 无泳道流程（推荐单列主链 + 右列分支）
1. 从 PRD 提取 `开始(start) → 主干步骤 → 判断(gateway) → 分支… → 结束(end)`。
2. 主干（主路径）自上而下排在第 0 列：第 i 个主干节点
   `x = 80`，`y = 60 + i × 120`（相邻节点垂直间隔 120，5px 对齐 ✓）。
3. 判断节点的每个分支，各占一个右列（col = 1, 2, …）：
   `x = 300 + (col-1) × 220`，该列内的节点按拓扑顺序从上往下：`y = 60 + row × 120`。
4. 分支结束若汇合回主干，连线从分支列斜回主干（jsPlumb 自动绕线，无需人工坐标）。
5. 主干每个判断节点之后的分支尽量让各分支内部步骤数接近，减少回头线。

### 4.3 泳道图（**默认：纵向泳道列 y-lane，泳道1/泳道2 水平并排、贴紧无间隙、顶部对齐**）
用户期望的泳道形态 = **若干条纵向泳道列（y-lane）从左到右水平排列**（如"泳道1 ｜ 泳道2"），
所有泳道**顶部在同一水平线（y 相同）且彼此贴紧（无间隙）**，流程步骤落在各自泳道列内。
不要默认使用上下堆叠的 x-lane 横带（仅当用户明确要"横向泳道带"时才用）。

泳道在 VFD 中是"视觉容器矩形"，节点不绑定容器，靠**坐标落在矩形内**实现归属。

0. **顶部标题横条**：nodeList 首位放一根整宽 `y-lane`（`width`=所有泳道宽度之和、`height≈45`、`y=0`），
   nodeName 写清"这是什么流程图"（如 `XXX系统 · 泳道流程图 —— 主流程说明`）。**标题条下边与第一行泳道顶边贴合**（泳道 y = 标题条高度）。
1. 泳道列：第 i 条 y-lane：`y` 全部相同（=标题条高，与标题条下边贴合）；`x` 依次**紧贴**排列（`x_i = x_{i-1} + width_{i-1}`，无间隙）；
   各泳道宽度按内容定，高度取同一值（盖住最下方节点 + 余量）。
   **泳道名称显示为与泳道同宽的通栏标题带**（预览/VFD y-lane 顶部横向色带，宽度=泳道宽度、名称水平居中）。
2. 泳道内排布：**行号 = 全局时序行**（整张图同一时间轴，每一步占一行、行内只有一个节点，另一侧泳道该行留空）：
   `y = laneY + 60 + t × 110`（t 为全局第几步）；这样跨泳道的横向段与竖直段都只经过"空行/泳道内侧空白带"，不会撞上任何节点。
   需要并列的子链放该泳道内的右副列（x 偏移，仅该行占用），相应加宽泳道。
3. **连线布线（硬性，禁止线段穿过节点矩形）**：
   - 同泳道内相邻两步 → 竖直直连（两行之间无节点）；
   - 跨泳道连线 → 从源侧边水平进"对侧泳道内侧空白带" → 竖直走到目标行 → 水平入目标侧边；
   - 同泳道跳线 / 指向本泳道右副列 → 走"泳道右内侧空白带"（或主列-副列间隙）；
   - 竖直段只允许出现在泳道内侧空白带 / 主副列间隙的固定 x 上；水平段只允许出现在空行或目标行。
   - **锚点模型与选点（硬性）**：每个元素（无论何种形状）固定 **4 个锚点 = 上/下/左/右边中点**，连线只能从这些锚点出/入。
     连接两个元素时，**枚举「出锚 × 入锚」的全部组合（≤16）**，每一组合用布线规则试跑，按
     **① 可通（路径在空白中）→ ② 转角最少（直线 0 转角 < 折线 1 转角 < …）→ ③ 总长最短** 选出最优并固定；
     同节点内 **入锚之间不重复、出锚之间不重复**（先来先占，冲突则取次优组合）。
   - **出入端口分离（硬性）**：同一节点上，任意入线与出线**不得共用同一个锚点**。
     分配习惯：入边优先 top/left，出边优先 bottom/right；节点的每条边都要独占一个锚点
     （上下左右四个边中点/顶点，最多 4 条），同侧多线时把其中一条改走相邻边，或用不同走廊
     （如菱形"是"走右走廊、"否"走下/左）。实现上用**每节点一张统一锚点占用表**——任一锚点
     无论被入线还是出线占用即锁定（"入口与出口永不同点"）。排布前先为每个节点做锚点占用表自查。
   - **单锚点单线（硬性 + 分级兜底）**：**一个锚点同一时间只能走一条线**（入或出，二选一）。
     放宽必须**分级**：① 严格：锚点与车道都唯一；② 若车道不足，先只**放开车道（允许共段）但锚点仍唯一**；
     ③ 仅当连②也无解（该节点所有锚点都不可用）的**极限情形**，才允许两条线共用某个锚点——共点永远是最后一级、显式的兜底。
   - **连线文字防重叠（硬性）**：当两条线段相交或相距很近且都带文字时，**文字之间必须保持安全距离**
     （不重叠、间隔 ≥ 若干 px），且不得压住元素。实现：先汇总所有带文字的线，沿每条路径采样候选点，
     逐个放置并避开"已放文字 + 元素"，尽量靠近路径中点。
   - **扇入/扇出末段（允许有限重叠）**：多条连线汇聚到同一目标（或同源分发）时：
     (1) 各线使用不同锚点；
     (2) **中间段（转角与转角之间）绝不允许共线重叠**（保持车道/并行）；
     (3) **末段（最后一个转角之后进入锚点的一段）允许重叠**——但前提是**双方末段都无文字**；
         只要任一末段上要放文字，该末段就**不得与其它线段重叠**（含末段-末段）；
     (4) 默认仍尽量让末段平行错开，重叠只是"无文字汇流"时的允许项，不是常态。
   - **布线判定规则（按顺序判断，硬性；线型只允许水平/竖直，禁止斜线）**：
     ① **直线判定**：两个元素在**同一条水平线或竖直线上**，且两点之间**畅通（有足够空余空间支持）** → 直线（0 转角）；
     ② **折线判定**：两个元素不在同一条线上（或直线被挡）→ 默认 **L 型、恰好 1 个转角**（两条候选 L 中取可行且较优的一条）；
     ③ **避障判定**：1 个转角的路径被元素节点挡住 → 自动绕开，此时**才允许转角 >1**（转角数尽量少、路径尽量短）。
     禁止斜线，禁止线段穿过/擦碰节点；同节点入/出锚点不共用规则同时生效。
   - **禁贴边（硬性）**：任何折线段不得与**任意元素（含起止点元素本身）的边共线并存在长度重叠**——
     不允许沿某元素的 上/下/左/右边滑行后再拐入。线段只允许在锚点处**垂直切入/切出**（单点接触）。
     例："昵称设置引导 → 校验并写入昵称"不得沿"校验并写入昵称"的上边横走后再下拐，
     应改为在该元素**左边中点**水平进入。
   - **转角留距（硬性）**：折线的**转角点不得离任何元素（含源/目标自身）太近**——路由搜索阶段即禁止在
     任一元素矩形外扩 18px 的范围内转弯（硬约束），并叠加 24→20→16→12→8→4→0 逐档校验，优先大间距。
   - **线段留距（硬性）**：**不仅转角，整条线段（每一段水平/竖直段）都必须与元素矩形保持安全距离**——
     路由时把元素矩形作为障碍外扩 ≥14px（任意线段不得进入该膨胀区；仅源/目标自身的锚点垂直贴接段除外）。
   - **具体标注（内容规则）**：每个节点都写具体动作/对象，不许用含糊词；
     圆形起止节点采用"框内短词 + 框下小字完整含义"（例：🔴 圆内"结束"，圆下
     "终止·今日已签到：同日已签 / 被其他标签页抢先，积分不变"；🟢"开始"，圆下"流程起点：用户打开 H5 页面"）；
     判断问题写在菱形内、条件走向写连线 label——图内所有信息不得靠猜。
4. 连线恒为直角折线（`"Flowchart"`），判断条件写连线 label；泳道节点与标题条不连线。
5. 泳道标题 = 角色名；角色是外部系统/客户也单独成列。

### 4.4 汇总结
- 所有坐标 ≥ 0，5px 对齐。
- 泳道容器尺寸：height ≥ 200、width ≥ 300 且能包住内部节点右/下边缘；泳道节点不连线。
- 普通节点 50×50（圆形/菱形）或 120×50（矩形）；label 过长时可考虑拆成多个节点。
- **起止唯一**：全图**恰好 1 个 start 与恰好 1 个 end**；多条终止路径（如"已签到/被拦截"与"签到成功"）必须汇聚到**同一个结束节点**（连线可分别标注原因）。
- **观感目标 = VFD 工程原生效果：方块节点、纵向泳道列贴紧并排、顶部标题条、直角折线、无曲线**。

## 5. 生成检查清单（交付前逐条自查）

- [ ] 字段完整：nodeList / linkList / attr.id / config.showGrid / status:"1" / remarks:[]
- [ ] 每个节点：type ∈ 9 类；nodeName 非空；id 文件内唯一；x、y、width、height 数字
- [ ] 每个连线：sourceId、targetId 都存在于 nodeList；无自连；无同向重复边；label 写了条件/动作
- [ ] 无泳道：恰好 1 个 start、≥1 个 end；有判断必有 ≥2 条出边且 label 标注各自条件
- [ ] 泳道：泳道节点在 nodeList 最前；默认 y-lane 纵向泳道列并排、顶部同一 y；普通节点坐标都落在所属泳道内；泳道无连线
- [ ] 布线不穿框：跨泳道/跳线均走走廊（泳道内侧空白带/主副列间隙），竖直段只在走廊内，无线段穿过节点矩形（坐标校验 + 预览目检）
- [ ] 端口分离：任一节点上入线与出线的锚点均不重合（统一锚点占用表；排布前自查 + 目检预览确认）
- [ ] 单锚点单线：同一锚点同一时间只走一条线；仅极限（无空锚点）时允许复用并显式兜底（目检预览）
- [ ] 文字防重叠：相交/相近且带文字的线段，其文字保持安全距离、不压元素（沿路径采样避让，目检预览）
- [ ] 扇入/扇出平行：中间段不共线重叠；末段仅"双方无文字"时允许重叠，带文字末段不得与任何线重叠（目检预览）
- [ ] 布线判定：全程仅水平/竖直无斜线；同行/同列且畅通 → 直线 0 转角；否则 L 型 1 转角；1 转角被挡才允许 >1 转角避障（引擎自检 + 目检）
- [ ] 线段留距：任意线段与元素矩形保持 ≥14px（含转角留距 ≥18px；源/目标锚点贴接段除外）（引擎自检 + 目检）
- [ ] 禁贴边：任意线段不与任何元素边共线重叠（无沿边滑行），仅在锚点垂直切入/切出（引擎自检 + 目检）
- [ ] 具体标注：普通节点写具体动作；起止圆"圆内短词+圆下完整含义"；判断问题在菱形内、条件在连线上
- [ ] 连线风格：所有 link 的 cls.linkType 为 "Flowchart"（直角折线，无曲线）；跳线走廊无中间节点阻挡
- [ ] 尺寸统一：矩形类节点一律 120×50、圆形/菱形类一律 50×50（不含泳道）；泳道全部等宽
- [ ] 判断文案：二值判断出边 label 为 是（…）/否（…）；非二值条件分支 label 写明条件文本
- [ ] 坐标：全部 5px 对齐、≥0；同一泳道内节点互不重叠（水平间距 ≥120、垂直间距 ≥60）
- [ ] JSON 语法：UTF-8 编码、无 BOM、无尾逗号、中文不转义也合法（`\uXXXX` 亦可）

## 7. 三种流程类型（先定类型，再按类型拆泳道）

> 铁律：**所有流程图（业务/任务/页面）一律采用泳道图结构**；**即便只有一个角色也必须拆出 ≥2 个泳道**，
> 用泳道区分"动作发出者"与"动作接收/反馈者"。类型由其"语境/层级"决定，**产出前必须先确认类型**。
> §1–§5 的格式与布线规则（纵向泳道列贴紧并排、顶部对齐、标题条贴合、等宽居中泳道名、4 锚点、折线、
> 安全距离、文字防重叠、锚点单线、起止唯一…）对三种类型全部生效，仅泳道划分与内容元素按下表执行。

| 类型 | 层级/语境 | 泳道拆分标准 | 内容元素 | 严禁 |
|---|---|---|---|---|
| **业务流程图** | 宏观（业务规则/跨方协同） | 多角色按实际参与方；**单角色强制拆【业务发起方】+【业务处理方】**（如单机 App → 【用户侧】+【系统内部处理】） | 只放**业务事件**（提交工单 / 审核通过 / 资金到账）；不得出现页面名与点击动作 | 页面名、UI 点击动作进入业务泳道 |
| **任务/功能操作流程图** | 中观（一次功能的操作路径） | **固定双泳道：A【用户操作】+ B【系统反馈】** | A：物理动作（点击、长按、输入、扫脸…）；B：加载中、弹窗、数据校验结果、成功/失败状态；**判断（菱形）属于 B 系统反馈** | 用户点击与系统校验混放同一泳道 |
| **页面流程图** | 微观（页面跳转路由） | **固定双泳道：A【当前页面/来源页】+ B【目标页面/去向页】** | 只画**矩形页面框**；箭头=路由（跳转指向 B，返回则箭头从 B 指回 A） | 该图内严禁出现判断条件、校验成功/失败等任务流内容 |

通用注意：
- 泳道命名严格按上表（业务=参与方名 / 发起方与处理方；任务=用户操作|系统反馈；页面=来源页|目标页），不要自己起名。
- 其它所有规则不变：节点尺寸/菱形内嵌问题/是-否与条件标注/起止唯一/四锚点/车道与末段规则/线段与转角留距/文字安全距离等。唯一起止唯一对页面流程语义化为"首页/末页"时同样成立。

## 8. 校验门禁与修复循环（Agent 硬性流程，防死循环）

1. **先校验后交付**：产出 JSON 后必须按 §5 检查清单做**全量自校验**；全部通过才"确认交付"（并向用户简述通过要点）。未通过**禁止直接交付**。
2. **修复循环（最多 3 次全量校验）**：
   - (a) 生成**《问题日志》**：`outputs/流程图/校验日志/问题日志_[项目]_[类型]_[日期].md`，每条含 编号 / 违反规则（§）/ 现象（节点与线段）/ 修复方案；
   - (b) 逐条修复，并同步写**《修改日志》**：`outputs/流程图/校验日志/修改日志_[项目]_[类型]_[日期].md`，每条含 编号 / 对应问题 / 改动内容 / 文件；
   - (c) 修复完成后做**第 2 次全量校验**；仍未通过则再修再检（**第 3 次为上限**）。
3. **三次未过立即停止**：不得继续循环；把《问题日志》《修改日志》与当前流程图（JSON + 预览 HTML）一起发给用户，列出"已尝试方案"与"剩余问题"，请用户**拍板**（接受现状 / 调整规则 / 手工修改 / 换布局），按指示继续。
